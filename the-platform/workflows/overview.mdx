## What Are Workflows?

A **Workflow** in Plura AI is a structured conversational system that breaks interactions into goal-oriented components, each represented by a **node** with a distinct purpose. Nodes are linked through **connectors**, which control the conversation flow based on predefined conditions.

This structured approach helps the AI maintain consistency, ensuring a logical sequence while preserving a natural and fluid dialogue experience.

## Channel Types

A **channel type** defines which communication channel the AI uses during the workflow. Every workflow is assigned a single channel type at creation.

- <Icon icon="phone" color="#F97316" />  **Voice**: Outbound and inbound calls.
- <Icon icon="message-circle" color="#3B82F6" />  **Webchat**: Web chat widget conversations.
- <Icon icon="message-square" color="#10B981" />  **SMS**: Text message conversations.
- <Icon icon="message-square-dashed" color="#EAB308" />  **RCS**: Rich Communication Services.
- <Icon icon="earth" color="#06B6D4" />  **Omnichannel**: A special channel type that lets the workflow use any channel internally rather than being locked to one.
- <Icon icon="workflow" color="#F87171" />  **Cadence**: Used when no specific communication channel is present. Acts as a master workflow that initiates and controls other workflows.

## Navigating the Workflow

Understanding the workflow interface is essential for building and managing AI-driven conversations effectively. Below is an overview of the key navigation components:

- **Node Library:** The sidebar where all node types live, organized into categories (Interactions, Functions, Logic, Timing, Other). Add a node to the canvas by clicking it or dragging it in. The **Universal Prompt** is also accessible from the Library.
  <img
    width="400"
    src="/images/node-section.png"
    style={{ width:"55%" }}
  />
- **Workflow Control Bar:** Contains essential tools for managing versions, monitoring performance, and testing the workflow.
  <img
    width="600"
    src="/images/top-bar.png"
  />
  - **Versions:** View and select different versions of your workflow to track changes and roll back if necessary.
  - **Show Analytics:** Provides insights into the performance of each node, helping you optimize the workflow.
  - **New Version:** Creates a new version of the workflow, maintaining previous iterations.
  - **Issues:** Surfaces validation problems in the workflow before publishing.
  - **Test:** Opens the Test Bench, enabling you to chat or call the workflow and observe its real-time behavior.
  - **Save & Publish:** The save button saves the workflow changes; the publish button deploys the workflow to either development or production.
- **Navigation Bar:** A floating toolbar that provides canvas-level controls for editing and viewing the workflow.
  <img
    width="400"
    src="/images/navigation-bar.png"
    style={{ width:"57%" }}
  />
  - **Undo / Redo:** Step backward or forward through recent changes.
  - **Duplicate:** Copy selected nodes on the canvas.
  - **Lock:** Locks the canvas to prevent accidental edits.
  - **Zoom Controls:** Zoom in, zoom out, or jump to a specific zoom level.
  - **Fullscreen:** Expands the workflow editor to fill the screen.
  - **Minimap:** Toggles a small-scale overview of the entire workflow for easier navigation.

## Components of a Workflow

A Workflow consists of the following key elements:

<Steps>
  <Step title="Nodes">
    Nodes are the building blocks of a Workflow. Each node serves a unique purpose and helps structure the conversation logically.

    <img
      width="500"
      src="/images/nodes.png"
      style={{ width:"73%" }}
    />

    Some of the primary node types include:

    - <Icon icon="message-bot" color="#60a5fa" />  **AI Conversation Node**: The core node where you provide specific instructions to the AI for handling a segment of the conversation.
    - <Icon icon="book-open" color="#c084fc" />  **Knowledge Base Node**: Enables the AI to retrieve relevant information from a predefined knowledge source.
    - <Icon icon="phone-slash" color="#f87171" />  **End Call Node**: Terminates the conversation when a specific outcome is reached.
    - <Icon icon="headphones" color="#4ade80" />  **Transfer Call Node**: Redirects the conversation to a human agent or another department.
    - <Icon icon="globe" color="#22d3ee" />  **API Call Setup Node**: Allows integration with external systems by making API requests to fetch or send data.

    See [Nodes](/the-platform/workflows/nodes/overview) for the full catalog of node types.
  </Step>
  <Step title="Connectors">
    Connectors link nodes together and control the flow of a conversation. Each connector has conditions that must be satisfied before progressing to the next node.

    <img
      width="500"
      src="/images/decision-trigger.png"
      style={{ width:"69%" }}
    />

    Plura supports multiple connector types, each suited to a different routing pattern:

    - <Icon icon="git-branch" color="#c084fc" />  **Decision Trigger**: Routes the conversation based on what the user said or how they responded. Used on AI Conversation nodes.
    - <Icon icon="filter" color="#fbbf24" />  **Condition Branch**: Routes based on data conditions using AND/OR logic. Used on Condition nodes.
    - <Icon icon="arrow-right" color="#4ade80" />  **Next**: A simple linear progression to the next node. Used on Function nodes that always flow through after completing.

    See [Connectors](/the-platform/workflows/connectors) for the full breakdown of each type.
  </Step>
  <Step title="Universal Prompt">
    The **Universal Prompt** is a predefined prompt that remains active throughout the entire workflow, regardless of which node the AI is currently on.

    <img
      src="/images/universal-prompt.png"
      alt="images/universal-prompt.png"
      style={{ width:"36%" }}
    />

    It plays a crucial role in guiding the call, maintaining context, and ensuring a consistent tone throughout the interaction. The Universal Prompt is accessible from the Node Library.
  </Step>
</Steps>

## Why Use Workflows?

- **Consistency**: Ensures the AI follows a structured and logical conversation flow.
- **Modularity**: Allows different parts of the conversation to be broken into manageable segments.
- **Flexibility**: Enables dynamic routing based on real-time inputs and conditions.
- **Scalability**: Facilitates building complex conversational systems without overwhelming the AI with excessive instructions at once.
